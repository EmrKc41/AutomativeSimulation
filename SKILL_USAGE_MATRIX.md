## Notes on skills deliberately not used

**`framer-motion` (Phases 3-4).** The command centre has motion, but all of it is
state-driven and expressible in CSS: meter widths that track utilisation and
operation progress, buffer slots that fill, and a colour transition on status
change. There is no enter/exit choreography, no gesture, no layout animation and
no shared-element transition — so a spring/gesture library would have added a
runtime dependency without adding operational meaning, and the project's own
rule is that every animation must mean something.

Phase 3 predicted this would change in Phase 4. It did not: the only motion the
3D view added is camera transitions and body easing, and both live inside the
WebGL scene (`CameraControls.setLookAt`, per-frame interpolation) where a DOM
animation library cannot help. Recorded here rather than quietly dropped.

**Every NVIDIA skill.** None were used in Phases 1–3, and the matrix above
records why: these phases are production engineering, an operational data model,
and an operator interface. The first honest use is Phase 6, where the simulated
`Inspection` contract is replaced by a real DeepStream/TAO pipeline publishing
the same shape.
